# PassGuard — управление секретами

Курсовая работа по дисциплине «Управление информационной безопасностью».
Тема 7: «Безопасное хранение и замена паролей и ключей».

**Этап 1:** локальный стенд Vault + PostgreSQL + FastAPI, получение пароля
из защищённого хранилища, его фактическая замена в PostgreSQL и проверка
того, что старый пароль перестал приниматься.

## Что реализовано

- Vault в обычном серверном режиме с постоянным Raft-хранилищем.
- TLS с проверкой локального центра сертификации для Vault и PostgreSQL.
- Автоматическая первоначальная настройка, без паролей в исходном коде.
- Отдельные AppRole-идентичности для приложения и оператора ротации.
- Приложение читает только свой пароль; оператор может заменить пароль,
  но не может прочитать его.
- Учебная учётная запись БД читает только таблицу `demo.documents`.
- Реальная ротация через Database Secrets Engine Vault.
- Аудит обращений к Vault; начальный root-токен отзывается после настройки.
- Повторное получение секрета при его изменении между чтением и подключением.
- Автоматическое испытание с отчётом, в котором нет значений секретов.
- Модульные проверки и workflow GitHub Actions для проверки живого стенда.

Панель React, авторизация пользователей панели, Gitleaks и ИИ-помощник
добавляются следующими этапами. На этом этапе HTTP API демонстрирует
только чтение учебных данных, а ротация запускается локальной командой оператора.

## Быстрый запуск на Windows

Нужен запущенный **Docker Desktop** в режиме Linux containers с Docker Compose v2.
Python и PostgreSQL на компьютер устанавливать не требуется.
Клонируй репозиторий и открой его папку в VS Code:

```powershell
git clone https://github.com/Ghost2772/passguard.git
cd passguard
code .
```

Также можно извлечь архив проекта. Выполняй команды в PowerShell
из папки, содержащей `compose.yaml`.

```powershell
docker version
docker compose version
```

Собери служебный образ и демонстрационное приложение:

```powershell
docker compose --profile ops build
```

Создай локальные сертификаты и начальный пароль БД:

```powershell
docker compose run --rm --no-deps tools python -m scripts.prepare
```

Запусти хранилище и БД, затем выполни первоначальную настройку:

```powershell
docker compose up -d postgres vault
docker compose run --rm tools python -m scripts.bootstrap
```

Дождись сообщения об успешной настройке и запусти приложение:

```powershell
docker compose up -d --wait demo
docker compose ps
```

Открой:

- Документацию API: <http://localhost:8001/docs>
- Учебные документы: <http://localhost:8001/api/documents>
- Проверку готовности: <http://localhost:8001/ready>

Ожидаемый ответ с документами:

```json
{
  "items": [
    {"id": 1, "title": "Политика управления секретами"},
    {"id": 2, "title": "Порядок замены паролей"}
  ]
}
```

## Испытание для курсовой

```powershell
docker compose run --rm tools python -m scripts.verify_rotation
```

Проверка выполняет настоящие обращения к Vault, PostgreSQL и приложению:

1. Подтверждает работу приложения до замены.
2. Получает старый пароль в память испытательного процесса.
3. Проверяет, что приложению запрещена ротация, а оператору запрещено чтение пароля.
4. Проверяет запрет записи на уровне прав PostgreSQL.
5. Вызывает ротацию статической роли в Vault, изменяющую пароль пользователя БД.
6. Подтверждает изменение пароля.
7. Создаёт **новое** соединение со старым паролем и ожидает именно ошибку авторизации.
8. Создаёт новое соединение с актуальным паролем и проверяет успех.
9. Выполняет пять запросов к приложению без его перезапуска.

При успехе выводится `"status": "passed"`, а результат сохраняется
в `reports/rotation.json`. Отчёт содержит результаты проверок и время,
без паролей, токенов и строк исходного кода. Если повторное испытание
завершилось ошибкой, отчёт заменяется результатом `failed`.

Смена пароля PostgreSQL сама по себе не закрывает уже установленные соединения.
Поэтому испытание проверяет именно новые подключения. Для случая активной
компрометации прекращение прежних сессий рассматривается отдельно.

## Остановка и повторный запуск

```powershell
docker compose down
```

Данные PostgreSQL, секреты и журнал Vault остаются в именованных томах Docker.
При перезапуске обычный Vault находится в запечатанном состоянии; разблокируй его:

```powershell
docker compose up -d postgres vault
docker compose run --rm tools python -m scripts.unseal
docker compose up -d --wait demo
```

Повторный `scripts.prepare` сохраняет существующие материалы. Повторный
`scripts.bootstrap` после завершённой настройки только разблокирует Vault
и не пересоздаёт секреты. Не удаляй `.local/`: в ней находятся данные доступа
и ключ разблокировки. Не используй `docker compose down --volumes`
для обычной остановки: эта команда удаляет данные стенда.

## Диагностика

```powershell
docker compose ps
docker compose logs --tail 60 postgres vault demo
```

- Docker не отвечает: запусти Docker Desktop и дождись готовности.
- Есть сообщение об отсутствии secret-файла: выполни `scripts.prepare`.
- Vault запечатан: выполни `scripts.unseal`.
- Порт 8001 занят: измени только левую часть привязки порта для `demo`
  в `compose.yaml`, например `127.0.0.1:8011:8001`.
- Нельзя скачать образы: проверь доступ Docker Desktop к Docker Hub.
- После восстановления только части файлов не запускай повторную генерацию
  поверх работающего стенда: ключи и данные должны принадлежать одной установке.

## Проверки разработки

Для локального запуска тестов нужен Python 3.12:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
```

Модульные проверки используют тестовые ответы Vault и имитацию соединений БД.
Они проверяют обработку ошибок, повторную авторизацию, обновление пароля при
подключении, ограничение повторов и отсутствие чувствительных значений в ответах.
Они не заменяют испытание настоящих Vault и PostgreSQL.

GitHub Actions запускает модульные проверки и отдельное интеграционное задание:
сборку Docker, первоначальную настройку, ротацию и повторную проверку после
перезапуска Vault. Если workflow ещё не запускался, интеграционная проверка
не считается пройденной.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/passguard/` | FastAPI, клиент Vault, подключение к PostgreSQL |
| `scripts/` | Подготовка, первоначальная настройка, разблокировка, испытание |
| `infra/vault/` | Настройка Vault и политики доступа |
| `infra/postgres/` | TLS-запуск PostgreSQL и правила аутентификации |
| `tests/` | Модульные проверки |
| `.github/workflows/ci.yml` | Проверки в GitHub Actions |
| `docs/architecture.md` | Архитектура, границы доверия и ограничения |
| `docs/roadmap.md` | Последующие этапы курсовой |

В `.local/` генерируются ключи и идентификаторы конкретной установки.
Эта папка исключена из Git и Docker build context. Docker Compose secrets
в локальном режиме используют файлы хоста: они не являются самостоятельным
зашифрованным хранилищем и требуют защиты диска и доступа к компьютеру.
