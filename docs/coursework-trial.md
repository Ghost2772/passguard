# Учебное испытание PassGuard

Цель испытания из задания курсовой: заменить учебный пароль и подтвердить,
что приложение продолжает работать, а старый пароль больше не принимается.

Объект проверки — пароль пользователя PostgreSQL `demo_reader`, которым
управляет роль Vault `demo-db`. Пароль личного входа администратора панели
в испытании не меняется. Рабочие секреты будущего магазина в эксперимент
не включаются.

Проверку выполняет `scripts.verify_rotation`. Он использует отдельные
служебные идентичности потребителя и оператора ротации. Веб-пароль
администратора скрипту не требуется, поэтому его смена в «Мой аккаунт»
не мешает этому испытанию.

Выполняй шаги в PowerShell из корня своей рабочей копии, содержащей
`compose.yaml` и локальное состояние этого стенда. Если контейнеры уже
запущены и готовы, дополнительных команд настройки не нужно.

1. Убедись, что стенд работает:

   ```powershell
   docker compose ps
   Invoke-RestMethod http://127.0.0.1:8001/ready
   ```

   Демонстрационный сервис должен вернуть `status: ready`. При запечатанном
   Vault сначала выполни `docker compose run --rm tools python -m scripts.unseal`,
   затем `docker compose up -d --wait demo control`.

2. Зафиксируй данные до замены и состояние контейнера:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8001/api/documents | ConvertTo-Json -Depth 5

   $demoBefore = docker compose ps -q demo
   if (-not $demoBefore) { throw "Контейнер demo не запущен" }
   $startedBefore = docker inspect --format '{{.State.StartedAt}}' $demoBefore
   if ($LASTEXITCODE -ne 0 -or -not $startedBefore) { throw "Не получено время запуска demo" }
   ```

   Сохрани скриншот ответа с учебными документами. Переменные для сравнения
   сохраняются в этой сессии PowerShell; следующие шаги выполняй в ней же.

3. Запусти основное испытание:

   ```powershell
   docker compose run --rm tools python -m scripts.verify_rotation
   if ($LASTEXITCODE -ne 0) { throw "Испытание не пройдено; проверь вывод скрипта" }
   ```

   Команда сама выполняет настоящую замену учебного пароля. Старое и новое
   значения используются только в памяти проверочного процесса; в терминал
   и итоговый JSON они не выводятся. Повторный запуск выполняет новую ротацию.

4. Убедись, что приложение отвечает после замены и контейнер не перезапускался:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8001/api/documents | ConvertTo-Json -Depth 5

   $demoAfter = docker compose ps -q demo
   if (-not $demoAfter) { throw "Контейнер demo не запущен после испытания" }
   $startedAfter = docker inspect --format '{{.State.StartedAt}}' $demoAfter
   if ($LASTEXITCODE -ne 0 -or -not $startedAfter) { throw "Не получено время запуска demo после испытания" }

   [pscustomobject]@{
       same_container = ($demoBefore -eq $demoAfter)
       same_started_at = ($startedBefore -eq $startedAfter)
   }
   ```

   Ожидаются те же учебные документы, `same_container: True`
   и `same_started_at: True`. Это дополнительное подтверждение, что
   потребитель не был заменён или перезапущен между снимками состояния.

5. Открой отчёт и зафиксируй фактический результат:

   ```powershell
   Get-Content .\reports\rotation.json
   ```

   Ожидается `status: passed`, актуальное время `checked_at`, все проверки
   ниже со значением `true` и `successful_requests_after_rotation: 5`.
   На исходном стенде `documents_count` равно 2.

| Поле отчёта | Что подтверждает |
| --- | --- |
| `application_works_before` | Приложение читало документы до замены |
| `application_cannot_rotate` | Потребитель не имеет права менять пароль |
| `rotator_cannot_read_password` | Идентичность оператора ротации не читает пароль |
| `database_role_is_readonly` | Учётная запись потребителя не может записывать учебные данные |
| `password_changed` | Новое значение отличается от прежнего |
| `old_password_rejected_on_new_connection` | Старое значение отклонено именно при авторизации нового соединения |
| `new_password_accepted_on_new_connection` | Новое соединение с актуальным паролем успешно |
| `application_works_after_without_restart` | Потребитель выполнил запросы после замены без перезапуска из сценария |

Скрипт отдельно отличает отказ авторизации старому паролю от сетевой ошибки:
недоступность PostgreSQL сама по себе не считается успешной проверкой отзыва.
Существующие соединения PostgreSQL не закрываются автоматически при смене
пароля. Поэтому доказательство строится на новых соединениях.

Для протокола сохрани `reports/rotation.json`, скриншоты документов до
и после, вывод результата испытания и сравнение состояния контейнера.
Фактический статус и дату бери из своего запуска, а не из примера инструкции.
Вывод о прохождении делается только при выполнении всех критериев.

После успешного запуска можно использовать такую формулировку результата:

> При испытании выполнена замена пароля служебной учётной записи PostgreSQL.
> Новое соединение со старым паролем было отклонено ошибкой авторизации,
> с новым паролем — установлено. Демонстрационное приложение продолжило
> чтение учебных данных без перезапуска. Значения секретов в отчёт не включены.

Если преподавателю нужно показать управление через интерфейс, дополнительно
выполни в «Секреты» → «Заменить пароль» учебную ротацию, затем нажми
«Проверить приложение» и открой событие в журнале. Это отдельная операция.
Кнопка проверки потребителя подтверждает доступность; отказ старому паролю
доказывает описанный выше скрипт. Прямое обращение скрипта к Vault учитывается
в аудите Vault, а не как действие пользователя управляющего API.

Остальные требования показываются отдельно:

| Требование | Демонстрация |
| --- | --- |
| Разграничение доступа | Создать аудитора, войти под ним, показать чтение журнала и отсутствие возможности запускать ротацию/сканирование |
| Проверка исходников | Загрузить ZIP с учебной строкой пароля и показать очищенную находку |
| Обоснование хранения и замены | Описать роли, выдачу секрета потребителю, период ротации и действия при раскрытии |

Подготовка примера ZIP и обычная работа описаны в [руководстве пользователя](user-guide.md).
Исторические результаты выполненных проверок приведены в [протоколе разработки](verification.md).
