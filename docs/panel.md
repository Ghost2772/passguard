# Панель PassGuard — этап 4

Панель React + TypeScript собирается Vite и включается в Docker-образ
`control`. Статические файлы и управляющий API доступны на одном адресе.
Отдельный Node.js на компьютере для запуска стенда не требуется.

## Обновление после третьего этапа

Выполни команды в существующей папке проекта:

```powershell
git pull --ff-only
docker compose --profile ops build
docker compose up -d --wait demo control
docker compose run --rm tools python -m scripts.verify_panel
```

Панель: <http://127.0.0.1:8000/>. API и Swagger остаются по адресу
<http://127.0.0.1:8000/docs>. Пользователи, отчёты и секреты сохраняются.
Миграций БД на этом этапе нет. Если Vault запечатан после перезапуска,
сначала выполни `docker compose run --rm tools python -m scripts.unseal`.

Для первого входа открой локальный файл `.local/operator/control-admin.json`
на своём компьютере. Если ты уже изменил пароль администратора, используй
актуальный пароль: файл первого входа автоматически не обновляется.
Не публикуй файл и не включай его в скриншоты. `verify_panel` использует
первоначальные данные входа из этого файла, как предыдущие проверочные скрипты.

## Экраны

| Экран | Назначение |
| --- | --- |
| Обзор | Доступность Vault/БД, метаданные секрета, последние отчёты, права и действия |
| Секреты | Учётная запись, период замены, ручная ротация и проверка потребителя |
| Проверка исходников | Загрузка ZIP, история, поиск по находкам, пропущенные файлы и экспорт JSON |
| Журнал действий | События, фильтр по текущей странице, постраничный просмотр и подробности |
| Пользователи | Создание учётных записей, изменение ролей, включение и отключение доступа |
| Мой аккаунт | Текущая роль и смена личного пароля с завершением сессий |

Навигация, кнопки и серверные проверки соответствуют матрице прав:

| Действие | admin | operator | auditor |
| --- | --- | --- | --- |
| Читать метаданные и отчёты | Да | Да | Да |
| Запускать проверку исходников и потребителя | Да | Да | Нет |
| Менять пароль demo-db | Да | Нет | Нет |
| Читать журнал | Да | Нет | Да |
| Управлять пользователями | Да | Нет | Нет |
| Менять собственный пароль | Да | Да | Да |

## Поведение при ротации

Нажми «Заменить пароль», выбери причину и подтверди замену. Идентификатор
операции создаётся перед запросом и сохраняется в памяти панели. Если ответ
потерян, интерфейс показывает неподтверждённый результат, а «Повторить запрос»
использует тот же идентификатор. Серверная идемпотентность предотвращает
повторную замену пароля. Для зарегистрированной операции доступны проверки
статуса. Новая ротация автоматически не запускается.

До разрешения неопределённого результата панель предлагает проверить текущую
операцию. При переходе между разделами её идентификатор сохраняется в памяти.
При полной перезагрузке страницы память очищается: сохрани идентификатор и
проверь журнал, если результат не подтверждён. Смена пароля не закрывает ранее
установленные соединения PostgreSQL; проверка потребителя подтверждает его
текущую доступность, а полный эксперимент с новыми соединениями выполняет
`scripts.verify_rotation`.

## Работа с исходниками

Архив отправляется только после нажатия «Проверить исходники». Клиент проверяет
расширение ZIP и размер, сервер независимо проверяет структуру и лимиты.
После успеха открывается сохранённый отчёт. Нет автоматической ротации по
находкам; совпадения требуют проверки человеком. JSON-экспорт содержит тот же
очищенный отчёт. Правила и ограничения описаны в [проверке исходников](source-scanning.md).

## Защита панели

- Сессионная cookie остаётся HttpOnly/SameSite=Strict с путём `/api/control`.
  Панель не читает токен сессии и не записывает пароли, CSRF, содержимое файлов
  в localStorage или sessionStorage. CSRF хранится только в памяти клиента.
- В изменяющих запросах передаётся `X-CSRF-Token`. При ответе 401 рабочее
  пространство закрывается и предлагается повторный вход. Выход выполняется
  на сервере; при сетевой ошибке панель не объявляет сессию завершённой.
- Названия файлов и другие пользовательские строки отображаются как текст
  React; вставка HTML не применяется. CSP страницы разрешает скрипты, стили,
  шрифты и соединения с собственным origin; inline-скрипты и встраивание во
  фрейм запрещены. Шрифты включены в сборку, внешних CDN у панели нет.
- Скрытие кнопок дополнено проверкой роли в маршрутах интерфейса и в API.
  Неизвестные API-пути возвращают JSON 404, а не страницу приложения.
- У интерфейса есть мобильное меню, клавиатурный фокус, диалоги подтверждения,
  состояния загрузки и ошибок. Индикаторы и списки берутся из реального API;
  отсутствие отчётов отображается пустым состоянием.

Стенд рассчитан на локальный доступ с доверенного компьютера; адреса портов
остаются привязанными к loopback. Публикация на удалённом сервере потребует
отдельной настройки HTTPS, secure-cookie и разрешённых origins.

## Проверки и разработка

`scripts.verify_panel` проверяет HTML, доступность JS/CSS, CSP, прежнюю
авторизацию API и отсутствие значений секрета в его метаданных. Результат —
`reports/panel.json` с `status: passed`.

В CI запускаются Python-тесты, проверки клиента, TypeScript-сборка и пять
сценариев Playwright на настоящем Docker-стенде. Для браузерных испытаний
создаются отдельные учётные записи всех трёх ролей; после завершения доступ
к ним отключается. Пароль первоначального администратора не меняется.
Playwright trace, video и автоматические снимки при ошибках отключены,
чтобы не записывать формы и запросы входа. Для проверки внешнего вида CI
может вывести только два заранее выбранных снимка: обзор после входа
и мобильную страницу проверки без заполненных паролей.
Безопасные итоги сохраняются в `reports/panel-browser.json`.

Для разработки интерфейса отдельно нужен Node.js 24:

```powershell
cd frontend
npm ci
npm run dev
```

Сервер разработки проксирует API на `127.0.0.1:8000`. Для изменяющих запросов
добавь `http://127.0.0.1:5173` и `http://localhost:5173` к переменной
`CONTROL_ALLOWED_ORIGINS` в существующем `.env` и пересоздай `control`.
Сохрани остальные записи `.env`, включая `COMPOSE_PROJECT_NAME` своего стенда.
Для обычного запуска через Docker менять origins не требуется.

```powershell
npm test
npm run build
```

Браузерный набор `npm run test:e2e` предназначен только для одноразового
CI-стенда: он создаёт тестовые аккаунты и выполняет настоящую ротацию.
