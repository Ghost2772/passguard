# План курсовой

| Этап | Результат | Проверка |
| --- | --- | --- |
| 1. Инфраструктура и потребитель | Vault, PostgreSQL, FastAPI, TLS, AppRole, ротация | Новые соединения: старый пароль отклонён, новый принят, приложение отвечает |
| 2. Управляющий API | Учётные записи, сессии, роли администратора, оператора и аудитора | Запрещённые операции возвращают 403; права проверяются на сервере |
| 3. Проверка исходников | Gitleaks, стандартные и учебные правила, безопасные отчёты | Подготовленные находки обнаружены, значения удалены из результатов |
| 4. Панель React | Обзор, секреты, проверки, журнал, пользователи | Основные операции доступны по ролям и работают с настоящим API |
| 5. ИИ-помощник | Разбор очищенных находок и план замены | Контрольный секрет не попадает в запрос к модели |
| 6. Оформление | Политика хранения, матрица прав, порядок ротации, протокол испытаний | Связь каждого требования задания с реализацией и доказательством |

На этапе 2 управляющий API получает отдельную учётную запись и схему данных.
Пароль демонстрационного потребителя не используется для пользователей и аудита
самой панели. Пользовательские пароли хешируются Argon2id; интеграционные секреты
остаются в Vault. Ротация через HTTP появляется только вместе с авторизацией.

Для API-ключей применяется отдельный механизм хранения и адаптер целевого
сервиса. Изменение значения в KV-хранилище само по себе не отзывает ключ
у его поставщика. Сценарий PostgreSQL полностью реализует и проверяет фактическую
смену пароля; управляемый отзыв API-ключа добавляется как самостоятельное расширение.

ИИ-помощник получает только поля, разрешённые явной схемой: тип находки,
идентификатор файла, строку и технические метаданные. Код, исходный отчёт
сканера, значения и фрагменты секретов в запрос не включаются. Решения
об изменении прав и запуске ротации принимает авторизованный пользователь.
